# Что сделано в сессии

Дата: 2 ноября 2026. Репозиторий: https://github.com/alex1974134/avibordfront

В этой сессии собран фронтенд-прототип AivibeBoard и код отправлен в отдельный GitHub-репозиторий. Доска, задачи и AI по-прежнему демо-данные в браузере: своей базы и настоящей AI-модели нет. 4 ноября 2026 вход и регистрация переведены на Supabase Auth. 9 ноября 2026 интерфейс стал двуязычным: русский и английский. В тот же день код разложен по обязанностям, поведение экранов не менялось. Позднее в тот же день раздел «Мои задачи» (`/tasks`) стал списком **досок** пространства: создание в Supabase, редактирование и удаление пока только в UI (Zustand).

## Продукт

AivibeBoard — рабочее пространство для проектов, задач и знаний команды. Обзор собран полностью. Остальные разделы — рабочие страницы с фильтрами и действиями, а не пустые заглушки.

Два демо-пространства: Aivibe Studio (тариф Pro) и Northwind Labs (тариф «Команда»). Состояние доски живёт в Zustand и сбрасывается при полной перезагрузке страницы. Сессию входа держит клиент Supabase, она переживает перезагрузку. Старый локальный ключ `aivibe-auth` при запуске удаляется.

## Стек

- React 19, TypeScript, Vite 8
- Tailwind CSS 4 через `@tailwindcss/vite`
- React Router 7
- Zustand 5
- `@supabase/supabase-js` для входа, регистрации и сессии
- Lucide React, Framer Motion, шрифт Inter Variable
- `tailwind-merge` для классов кнопок, чтобы `hidden` не конфликтовал с базовым `inline-flex`

Ограничения сборки: `verbatimModuleSyntax` (импорт типов через `import type`), `erasableSyntaxOnly` (без enum), без `any`. Проверка: `npm run build` (`tsc -b` и `vite build`) проходит.

## Структура

```
src/
  app/          маршруты, защита страниц и корень приложения
  components/   layout и UI-кит
  pages/        страницы разделов и экран входа
  features/     задачи, доски, обзор, AI, команда, база знаний, Telegram
  data/         демо-данные
  i18n/         язык, словари и перевод демо-контента
  lib/          клиент Supabase и запросы к таблице досок
  supabase/     SQL-миграции для удалённого проекта
  store/        состояние доски, сессия входа, сборка записей и разбор ошибок входа
  hooks/        данные текущего пространства, закрытие по клику снаружи
  types/        Project, Task, User, Activity и остальные модели
  utils/        подписи, даты, поиск, почта, цвета участников, склонения
```

Черновик AI живёт рядом с экраном помощника: `features/ai-assistant/draftCatalog.ts` хранит шаги, `draftPlan.ts` собирает план, `useDraftGeneration.ts` держит состояние генерации. База знаний разделена на категории, зону загрузки, список и создание файлов. Проверка полей входа — в `pages/Auth/authIssues.ts`, поле пароля — в `PasswordField.tsx`, тексты ошибок Supabase — в `store/authErrors.ts`. Задачи и активность доски собирает `store/records.ts`. Общие куски: `utils/email.ts`, `utils/haystack.ts`, `utils/memberColor.ts`, склонения в `utils/format.ts`, нумерованные шаги в `components/ui/NumberedSteps.tsx`.

## Маршруты

| Путь | Раздел |
| --- | --- |
| `/login` | Вход |
| `/register` | Регистрация |
| `/dashboard` | Обзор |
| `/tasks` | Мои доски (список досок и задачи выбранной доски) |

Без сессии любой адрес, включая `/` и неизвестный путь, ведёт на `/login`. После входа человек возвращается на адрес, с которого его перенаправили, иначе открывается `/dashboard`. Если сессия уже есть, `/login` и `/register` тоже ведут туда. У авторизованного неизвестный адрес по-прежнему ведёт на `/dashboard`.

## Авторизация

Экран один: переключатель «Вход» и «Регистрация». На входе почта и пароль. На регистрации ещё имя и повтор пароля. Пароль не короче 6 символов. Общий демо-пароль больше не используется: почта и пароль проверяются в Supabase.

Пока запрос идёт, кнопка показывает «Подождите…» или “Please wait…”. Ошибки формы идут на выбранном языке: пустые поля, неверная почта, несовпадение паролей, занятая почта, неверная пара, неподтверждённая почта, слишком много попыток, отключённая регистрация. На этом экране нет шапки, поэтому переключатель языка стоит в правом верхнем углу.

Новый аккаунт создаётся через `signUp`. Имя и роль «Участник» уходят в metadata, человек попадает в пространство Aivibe Studio. Если Supabase требует подтверждение почты, сессия сразу не открывается: на экране остаётся просьба перейти по ссылке из письма. Ссылка ведёт на `/dashboard`. Если подтверждение выключено и сессия уже есть, открывается доска.

Выход есть внизу боковой панели и в карточке «Сессия» на странице настроек. Правка имени, роли и почты текущего пользователя отправляется в Supabase через `updateUser`. Остальные демо-данные доски по-прежнему сбрасываются при перезагрузке.

## Что умеет интерфейс

- Вход, регистрация и выход. Доска закрыта, пока сессии нет.
- Боковая панель около 250px: логотип, переключатель пространства, разделы, блок AI, Telegram, настройки, профиль и «Выйти». На узком экране панель открывается как выдвижное меню.
- Шапка: название раздела, хлебные крошки, поиск, переключатель RU | EN, «Новая задача», уведомления, аватар. Поиск фокусируется по Ctrl+K.
- Обзор: приветствие, счётчики, карточки проектов, свои задачи, блок AI и лента активности.
- **Мои доски** (`/tasks`): карточки досок с превью колонок задач; клик по карточке открывает доску. Кнопка «Новая доска» — название, описание, доступ участникам. Меню ⋯ на карточке и внутри доски: открыть, изменить, удалить. Изменение и удаление меняют только состояние в браузере; после перезагрузки подтянутся данные из Supabase, если пользователь вошёл.
- Создание доски при активной сессии пишет в Supabase (`boards`, `board_members`). Демо-доски из `data/mockProjects.ts` показываются вместе с досками из БД.
- Создание задачи, смена статуса, фильтры задач и проектов, приглашение участника, правка профиля, переключатели уведомлений.
- Поиск по проектам и задачам текущего пространства. Запрос ищет и русское, и английское название демо-записей.
- База знаний: категории, поиск, перетаскивание файлов. Файлы остаются только в сессии.
- Telegram: подключение имитируется, демо-адрес можно скопировать.
- AI: локальный черновик по тексту запроса, пауза 700 мс, без сетевого вызова. Ключевые слова на русском и английском выбирают тему (дизайн, маркетинг, интеграция). Задачи можно добавить на доску выбранного проекта.

## Язык

Два языка: русский и английский. По умолчанию русский. Выбор хранится в `localStorage` под ключом `aivibe-locale` и переживает перезагрузку. Атрибут `lang` у страницы совпадает с выбранным языком.

Переключатель RU | EN стоит в шапке и на экране входа. На выбранный язык переходят меню, страницы, формы, пустые состояния, тосты, статусы, приоритеты, сроки, относительное время, роли, демо-проекты, задачи, активность, уведомления и документы.

Свой текст остаётся как введён. Новая задача, приглашение и черновик AI сохраняются на языке, который был выбран в момент создания, и дальше не переводятся. Если демо-поле уже отредактировано и больше не совпадает со словарём, показывается введённое значение.

Оставлены как есть: название AivibeBoard, имена людей, адреса маршрутов и имена в коде. Категории документов в данных по-прежнему Product, Engineering, Design, Research, а на экране они показываются как Продукт, Разработка, Дизайн, Исследования или Product, Engineering, Design, Research.

Даты идут локалью `ru-RU` или `en-US`. Для русских счётчиков используется склонение: задача / задачи / задач и аналогичные формы. В английском — единственное и множественное число.

## Supabase: доски

Миграция `supabase/migrations/20261109170336_create_boards.sql`:

- `public.boards` — id, workspace_id (text), name, description, status, progress, task_count, deadline, created_by → `auth.users`, created_at.
- `public.board_members` — составная первичный ключ (board_id, user_id text); `user_id` допускает UUID участника и демо-id для прототипа.
- RLS: `authenticated` может читать; вставка в `boards` только если `created_by = auth.uid()`; вставка в `board_members` только для досок, созданных этим пользователем.

Клиент: `src/lib/boards.ts` — `fetchBoards(workspaceId)` и `createBoard(...)`. Стор: `remoteProjects` плюс демо-`projects` в `useWorkspaceData`; загрузка после входа и смены пространства (`loadRemoteBoards`).

Пока **нет** API для обновления и удаления досок в БД — только UI в `updateBoard` / `deleteBoard`.

## Git

Папка проекта лежит внутри другого репозитория (`webcode1`). Для AivibeBoard создан собственный `.git`, чтобы код не смешался с соседними проектами.

- Remote: `origin` → https://github.com/alex1974134/avibordfront.git
- Ветка: `main`
- Первый коммит: фронтенд-прототип

`node_modules` и `dist` в репозиторий не входят.

## Запуск

Нужен файл `.env.local` в корне. Он не попадает в git. Без этих переменных приложение не стартует:

```
VITE_SUPABASE_URL=https://<project>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<publishable-key>
```

```bash
npm install
npm run dev
npm run build
```

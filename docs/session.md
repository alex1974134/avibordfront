# Что сделано в сессии

Дата: 2 ноября 2026. Репозиторий: https://github.com/alex1974134/avibordfront

В этой сессии собран фронтенд-прототип AivibeBoard и код отправлен в отдельный GitHub-репозиторий. 4 ноября 2026 вход и регистрация переведены на Supabase Auth. 9 ноября 2026 интерфейс стал двуязычным: русский и английский. В тот же день код разложен по обязанностям, поведение экранов не менялось. Позднее в тот же день раздел «Мои задачи» (`/tasks`) стал списком **досок** пространства: создание в Supabase, редактирование и удаление доски пока только в UI (Zustand). 11 ноября 2026 задачи сохранённых досок создаются, меняются и удаляются в Supabase, а роль IT-команды выбирается при регистрации и в настройках и пишется в metadata пользователя. В тот же день добавлены Edge Function **openrouter** (OpenRouter, модель gpt-6-luna), лайв-чат на обзоре с контекстом, всплывающий AI на доске проекта для декомпозиции цели в задачи по ролям, 10 тестовых участников в демо-данных.

## Продукт

AivibeBoard — рабочее пространство для проектов, задач и знаний команды. Обзор собран полностью. Остальные разделы — рабочие страницы с фильтрами и действиями, а не пустые заглушки.

Два демо-пространства: Aivibe Studio (тариф Pro) и Northwind Labs (тариф «Команда»). Состояние доски живёт в Zustand и сбрасывается при полной перезагрузке страницы. Сессию входа держит клиент Supabase, она переживает перезагрузку. Старый локальный ключ `aivibe-auth` при запуске удаляется.

## Авторизация

Экран один: переключатель «Вход» и «Регистрация». На входе почта и пароль. На регистрации ещё имя, роль и повтор пароля. Пароль не короче 6 символов, роль обязательна. Общий демо-пароль больше не используется: почта и пароль проверяются в Supabase.

Пока запрос идёт, кнопка показывает «Подождите…» или “Please wait…”. Ошибки формы идут на выбранном языке: пустые поля, невыбранная роль, неверная почта, несовпадение паролей, занятая почта, неверная пара, неподтверждённая почта, слишком много попыток, отключённая регистрация. На этом экране нет шапки, поэтому переключатель языка стоит в правом верхнем углу.

Новый аккаунт создаётся через `signUp`. Имя и выбранная роль уходят в `user_metadata` (`name`, `role`), человек попадает в пространство Aivibe Studio. Роль — один из идентификаторов IT-команды: `frontend`, `backend`, `fullstack`, `mobile`, `qa`, `devops`, `admin`, `designer`, `analyst`, `pm`, `lead`. На экране они показываются как Frontend-разработчик, Backend-разработчик, Fullstack-разработчик, Mobile-разработчик, QA-инженер, DevOps-инженер, системный администратор, дизайнер, аналитик, менеджер проектов и тимлид (и те же роли по-английски). Если Supabase требует подтверждение почты, сессия сразу не открывается: на экране остаётся просьба перейти по ссылке из письма. Ссылка ведёт на `/dashboard`. Если подтверждение выключено и сессия уже есть, открывается доска.

Выход есть внизу боковой панели и в карточке «Сессия» на странице настроек. В профиле роль выбирается из того же списка, а не вводится текстом. Правка имени, роли и почты текущего пользователя отправляется в Supabase через `updateUser`; в metadata уходит идентификатор роли. Старая роль «Участник» в списке не выбрана: чтобы сохранить профиль, нужно выбрать роль из списка. Демо-данные доски по-прежнему сбрасываются при перезагрузке.

## Что умеет интерфейс

- Вход, регистрация и выход. Доска закрыта, пока сессии нет.
- Боковая панель около 250px: логотип, переключатель пространства, разделы, блок AI, Telegram, настройки, профиль и «Выйти». На узком экране панель открывается как выдвижное меню.
- Шапка: название раздела, хлебные крошки, поиск, переключатель RU | EN, «Новая задача», уведомления, аватар. Поиск фокусируется по Ctrl+K.
- Обзор: приветствие, счётчики, карточки проектов, свои задачи, блок AI и лента активности.
- **Мои доски** (`/tasks`): карточки досок с превью колонок задач; клик по карточке открывает `/projects/:projectId`. Кнопка «Новая доска» — название, описание, доступ участникам. Меню ⋯ на карточке и внутри доски: открыть, изменить, удалить. Изменение и удаление доски меняют только состояние в браузере; после перезагрузки подтянутся данные из Supabase, если пользователь вошёл.
- Создание доски при активной сессии пишет в Supabase (`boards`, `board_members`). Демо-доски из `data/mockProjects.ts` показываются вместе с досками из БД.
- Задачи сохранённой доски создаются, меняют статус, исполнителя, приоритет и срок и удаляются в Supabase (`tasks`). Задачи демо-досок остаются только в сессии. На доске проекта колонки соответствуют статусам, задачу можно перетащить между ними.
- Создание задачи, смена статуса, фильтры задач и проектов, приглашение участника, правка профиля, переключатели уведомлений.
- Поиск по проектам и задачам текущего пространства. Запрос ищет и русское, и английское название демо-записей.
- База знаний: категории, поиск, перетаскивание файлов. Файлы остаются только в сессии.
- Telegram: подключение имитируется, демо-адрес можно скопировать.
- **Обзор:** лайв-чат с моделью `openai/gpt-6-luna` через Edge Function `openrouter`; контекст диалога в рамках вкладки и пространства.
- **AI (`/ai`, `/ai/generator`):** локальный черновик по тексту (700 мс), без сети; задачи можно добавить на доску выбранного проекта.
- **Доска проекта (`/projects/:id`):** всплывающий AI — описание глобальной цели, ответ JSON, назначение по `teamRole` участников доски, кнопка «Добавить на доску» (Supabase для UUID-досок).
- В `data/mockUsers.ts` добавлены 10 тестовых участников (`u-test-01` … `u-test-10`) с разными IT-ролями для демо и назначений.

## Язык

Два языка: русский и английский. По умолчанию русский. Выбор хранится в `localStorage` под ключом `aivibe-locale` и переживает перезагрузку. Атрибут `lang` у страницы совпадает с выбранным языком.

Переключатель RU | EN стоит в шапке и на экране входа. На выбранный язык переходят меню, страницы, формы, пустые состояния, тосты, статусы, приоритеты, сроки, относительное время, роли, демо-проекты, задачи, активность, уведомления и документы.

Свой текст остаётся как введён. Новая задача, приглашение и черновик AI сохраняются на языке, который был выбран в момент создания, и дальше не переводятся. Если демо-поле уже отредактировано и больше не совпадает со словарём, показывается введённое значение.

Оставлены как есть: название AivibeBoard, имена людей, адреса маршрутов и имена в коде. Категории документов в данных по-прежнему Product, Engineering, Design, Research, а на экране они показываются как Продукт, Разработка, Дизайн, Исследования или Product, Engineering, Design, Research.

Даты идут локалью `ru-RU` или `en-US`. Для русских счётчиков используется склонение: задача / задачи / задач и аналогичные формы. В английском — единственное и множественное число.

## Supabase: доски

Миграция `supabase/migrations/20261109170336_create_boards.sql`:

- `public.boards` — id, workspace_id (text), name, description, status, progress, task_count, deadline, created_by → `auth.users`, created_at.
- `public.board_members` — составная первичный ключ (board_id, user_id text); `user_id` допускает UUID участника и демо-id для прототипа.
- RLS: `authenticated` может читать; вставка в `boards` только если `created_by = auth.uid()`; вставка в `board_members` только для досок, созданных этим пользователем.

Клиент: `src/lib/boards.ts` — `fetchBoards(workspaceId)` и `createBoard(...)`. Стор: `remoteProjects` плюс демо-`projects` в `useWorkspaceData`; загрузка после входа и смены пространства (`loadRemoteBoards`).

Пока **нет** API для обновления и удаления досок в БД — только UI в `updateBoard` / `deleteBoard`.

Миграция `supabase/migrations/20261109182851_create_tasks.sql`:

- `public.tasks` — id, board_id → `boards` (каскадное удаление), workspace_id, title, assignee_id (text, как у участника доски), priority, status, deadline, created_by → `auth.users`, created_at.
- Триггер пересчитывает `boards.task_count` при вставке и удалении задачи.
- RLS: `authenticated` может читать, обновлять и удалять; вставка только если `created_by = auth.uid()` и исполнитель есть в `board_members` этой доски.

Клиент: `src/lib/tasks.ts` — чтение, создание, правка и удаление. Стор вызывает эти функции для досок из Supabase и оставляет локальные задачи для демо-досок.

Для доски из Supabase (id в формате UUID) при активной сессии `addGeneratedTasks` и одиночное создание задачи всегда идут в БД; перед вставкой исполнитель должен входить в `board_members` (подставляется из списка участников доски, если модель ошиблась).

## Supabase: Edge Function openrouter

Исходник: `supabase/functions/openrouter/index.ts`. На проекте `kzpppkhjfgzocnzzfvwu`, JWT включён (`verify_jwt: true`).

- `POST` с `{ "prompt": "..." }` или `{ "messages": [...] }`, опционально `json: true` для `response_format: json_object`.
- Модель: **openai/gpt-6-luna** через [OpenRouter](https://openrouter.ai/openai/gpt-6-luna).
- Ключ **только** в секрете проекта `OPENROUTER_API_KEY` (Dashboard → Edge Functions → Secrets или `supabase secrets set`). В репозиторий ключ не кладётся.
- Клиент: `src/lib/openrouter.ts` — `callOpenRouterChat`, `callOpenRouterJson`.

```ts
await supabase.functions.invoke('openrouter', { body: { messages } })
```

## Запуск

Нужен файл `.env.local` в корне. Он не попадает в git. Без этих переменных приложение не стартует:

```
VITE_SUPABASE_URL=https://<project>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<publishable-key>
```

Для AI-чата и декомпозиции на доске нужен задеплоенный `openrouter` и секрет `OPENROUTER_API_KEY` в том же проекте Supabase.

```bash
npm install
npm run dev
npm run build
```

Локально функцию можно поднять через Supabase CLI (`supabase functions serve openrouter`); секреты — в `supabase/functions/.env` (не коммитить).
